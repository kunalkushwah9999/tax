# Finish the release outside ChatGPT

**Current application: 5.1.0 synthetic pilot. Public paid production release is
unfinished. Independent tax approvals remain 0/30.** The new tools automate local
Android prerequisite checks/unsigned builds and bounded HTTPS endpoint probes.
They do not implement missing statutory tax, grant approval or publish anything.

The downloaded Java/Python application and these scripts run without ChatGPT,
a Plus subscription or paid AI inference. Keep the ZIP locally. Java 17+ and
Python 3.10+ are needed for the normal app; Android builds have extra prerequisites.

## 1. Run the app and generate owner configuration

From the extracted project directory:

```sh
python3 manage.py doctor
python3 manage.py start
```

Open http://127.0.0.1:8788 and use **synthetic data**. Use `python` if that is the
installed command on your computer. `manage.py doctor` checks existing engineering
bindings; it does not independently approve financial calculations.

Generate a new origin-specific web/Android/cloud bundle, replacing all uppercase
examples with the owner's real lowercase values and paths:

```sh
python3 release/prepare.py --origin https://YOUR_DOMAIN --application-id in.YOUR_COMPANY.taxdesk --support-email support@YOUR_DOMAIN --out /NEW/BUNDLE_DIRECTORY
```

The output parent must exist and the output directory must be new. Uppercase
placeholder domains/IDs are deliberately rejected. No cloud account, API key,
private signing key or live provider enrollment is supplied by this command.

## 2. Check and build the Android source

Install an Android SDK with platform 36 and build tools 35.0.0, JDK 17+ and Gradle
8.13 for the generated AGP 8.13.2 project. Start with:

```sh
python3 release/android_build.py doctor --project /BUNDLE/android --sdk /ANDROID/SDK --gradle /PATH/TO/gradle --out android-doctor.json
```

Missing SDK/Gradle/source requirements produce exit **2** and an explicit failure
report. It does not invent an APK/AAB or download the SDK. With the prerequisites
installed, lint and build in a **fresh generated project**:

```sh
python3 release/android_build.py build --project /BUNDLE/android --sdk /ANDROID/SDK --gradle /PATH/TO/gradle --allow-dependency-download --out android-build.json
```

Without `--allow-dependency-download`, Gradle runs offline and needs previously
resolved dependencies. Gradle output stays on the local console. The JSON report
does not include raw build logs or credentials. An existing release AAB must be
moved aside or a fresh project generated before building, so an old output is not
mistaken for a new build. A successful run records the **unsigned** AAB path/hash.

**Signing/device testing/Play review are still required.** Use Android Studio's
Generate Signed Bundle flow with the owner's protected upload key, then configure
Play App Signing. No signing key or password is generated by this tool. Use Play's
app-signing certificate fingerprint in `--app-signing-sha256` when regenerating the
web bundle; the upload-key fingerprint can differ. See release/ANDROID_RELEASE.md.
The actual SDK/build/signing/device pipeline was unavailable here and is **not
reported as executed**. Android doctor tests are not Android build evidence.

## 3. Validate the actual HTTPS endpoint after deployment

Follow release/CLOUD_DEPLOYMENT.md to provision the owner VM, actual MySQL/TLS,
keys, Nginx and systemd service. After deployment, run:

```sh
python3 release/verify_site.py --origin https://YOUR_DOMAIN --out cloud-smoke.json
```

Optionally add both `--application-id` and `--app-signing-sha256` to check the
actual public Digital Asset Links against the Play app-signing certificate.
These are public identity values, not signing private keys. Output must be a new
file. No account password, real tax record, payment or filing is needed.

The bounded probes verify TLS with system trust, the expected app version and
unreleased-production flag, secure cookie attributes, no-store/HSTS/CSP headers,
private-API rejection, wrong Host/Origin rejection, receipt CSRF, generic unknown
receipt behaviour, manifest/worker, the public deletion page and Asset Links.
Redirects are not followed; oversized responses and malformed/incompatible data
fail. Cookie/CSRF/response bodies are excluded from reports. No customer account
or business record is created; the probes only establish temporary anonymous
sessions and read-only receipt queries.

**A passed endpoint smoke test is not cloud release validation.** The report keeps
`cloud_release_validated:false` and `production_ready:false`. It does not establish
authenticated customer behaviour, production Nginx execution, backup/PITR/control
reconciliation, monitoring, scale, provider certification or statutory approval.
`--fixture --ca-file` is reserved for explicitly labelled local TLS tests and can
never count as public-endpoint evidence. Public probes require standard HTTPS 443.

backend and a disposable explicitly trusted TLS proxy. Negative cases include
untrusted TLS, unsafe origins, private API exposure, missing headers, old versions,
redirects, mismatched signing identity and malformed JSON. Reports are checked for
cookie/CSRF leakage. Actual CLI execution and non-overwrite behaviour are tested;
Android doctor correctly reports a missing SDK/Gradle. **No actual Android SDK
build, public cloud deployment, Nginx process or external approval is claimed.**

The application runtime/source and previous component/golden evidence are unchanged.
Run `python3 release/test_operations.py` to repeat the tool checks (Java and OpenSSL
